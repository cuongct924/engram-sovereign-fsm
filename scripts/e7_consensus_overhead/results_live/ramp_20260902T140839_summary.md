# LIVE E7 throughput/latency A/B under real load

Real MsgSubmitForcedTxRequest load, ramp [5.0, 20.0, 50.0, 100.0] tx/s, 30s x 1 repeat(s) per mode/rate, 4 concurrent sender(s) per phase (round-robin across validators for extended). `extended` is measured against the real 7-validator engram-validator-cluster (already running, the same deployment E2/E4/E5/E6's data comes from); `vanilla` is a local single `engramd --vanilla` process this script owns -- a deliberate simplification (a second full 7-node vanilla cluster is a separate infra undertaking), so treat `vanilla` as a lower bound on overhead-free throughput, not a strict cluster-vs-cluster comparison. `blocks_per_sec` and `mean/p50/p95 interval` measure different things (module docstring) -- `steady_blocks_per_sec` (=1/mean interval) and `gap_fraction` reconcile them explicitly below.

## Ramp: throughput ceiling

Ceiling = the rate stage where `Tx-accepted/s` stops tracking the target rate (saturation), or where `Gap fraction`/`p95 interval` starts climbing sharply.
