# Formal verification results

Logs behind the formal results of the paper (Section 5, Appendix E). Each file is the raw TLC or Apalache output of one
run on the specification of the commit below, on an Apple M1 Pro (10 cores, 32 GB). TLC is 2026.04.18 (rev. c45c125) on
OpenJDK 11.0.31; Apalache is 0.58.3 on OpenJDK 21.0.2. The counterexample traces of the ablations are in `../traces/`
(`ablation_no_*.tlc.json`, TLC `-dumpTrace json`).

| Result | Log | Driver |
|---|---|---|
| Tendermint safety | `tendermint_safety.log` | `MC_TendermintSafety` |
| FSM safety | `fsm_safety.log` (10 workers); `fsm_safety_repeat.log` (6 workers) | `MC_FSMSafety` |
| FSM liveness | `fsm_liveness.log` | `MC_FSMLiveness` |
| Ablation: circuit breaker | `ablation_circuit_breaker.log` | `MC_Ablation_NoCircuitBreakerSafety_Apalache` |
| Ablation: hysteresis | `ablation_hysteresis.log` | `MC_Ablation_NoHysteresisSafety_FSMOnly_Apalache` |
| Ablation: P2P gate | `ablation_p2p_gate.log` | `MC_Ablation_NoP2PGateSafety_FSMOnly_Apalache` |
| Ablation: DA consistency | `ablation_da_consistency.log` | `MC_Ablation_NoDAConsistencySafety_Apalache` |
| Ablation: DA backfill | `ablation_da_backfill.log` | `MC_Ablation_NoDABackfillSafety_FSMOnly_Apalache` |

| Refinement C1, bound L0 | `c1/` | `MC_ServerRefinementVacuity`, `MC_ServerRefinementStep_Apalache` |

The ablation drivers keep the `_Apalache` suffix of the first Apalache version; every ablation here is run with TLC. The
configurations of `c1/` are generated by `tools/make_c1_cfgs.py` (`--layer server --ladder`).

`c1/` holds the existence checks: `vacuity_L0_RoundChange`, `vacuity_L0_ByzantineProposal` and `probe_HonestPrevotes` reach their
targets; `vacuity_L0_Decision_long`, `vacuity_L0_FSMTransition`, `probe_Lock`, `probe_happy_Decision`, `probe_tight2_Decision` and
`probe_nosym_R2_Decision` were stopped without reaching a decision (see `vacuity_L0_Decision_killed_note.txt`); `apalache_B1`
passes the base case of the inductive step and `apalache_B2` stops at the set filter over a powerset.

The circuit-breaker and DA-consistency rows are run on the specification in which a proposer validates against the certificate
it has just built (`IsValidProposalIn`, `InsertProposalWith`). The three FSM-layer ablations and the FSM rows do not depend on
that change.
