# Reproducing the build

The paper's results come from three repositories. Only the first is a build input of the node; the other two are pinned by hash.

| Repository | Role | How it is pinned |
|---|---|---|
| `engram-sovereign-fsm` (this repository) | the node, the prover, the circuits, the experiments | the commit of this checkout |
| [`engram-consensus-core`](https://github.com/cuongct924/engram-consensus-core) | the CometBFT fork used as the agreement core | `go.mod`'s `replace` line: a pseudo-version of commit `493a20121caa`; `go.sum` records its hash |
| [`engram-barretenberg-wasm`](https://github.com/cuongct924/engram-barretenberg-wasm) | source of the embedded UltraHonk verifier (`zk_assets/barretenberg.wasm.gz`) | `x/sovereignty/keeper/zk_assets/ASSETS.lock`: SHA-256 and source commit |

Nothing needs checking out beside this repository.

## Build and test the node

```bash
go build ./... && go vet ./... && go test ./x/... ./app/... ./cmd/...
scripts/verify_zk_assets.sh              # embedded verifier and verification keys match ASSETS.lock
scripts/verify_zk_assets.sh --rebuild    # also recompile the circuits and regenerate the keys (needs nargo 1.0.0-beta.22 and bb 5.0.0-nightly.20260522)
```

## Build the images

```bash
docker build -f Dockerfile -t engram-node .
docker build -f docker/reanchoring-prover/Dockerfile -t engram-reanchoring-prover .
```

Both Dockerfiles fetch only pinned inputs: the base images by digest, the fork through `go.sum`, `bb` and `nargo` from their
releases checked against SHA-256 hashes. Build on a native machine of the target architecture (an `amd64` build under emulation
crashes with SIGILL). The images the cluster runs are built from a clean checkout and pushed by `.github/workflows/images.yml` or
`deploy/bin/build-push-images.sh`, tagged with the commit (`deploy/README.md`, "Build the images").

## What the local build does not cover

- The embedded `barretenberg.wasm.gz` is committed as a binary. Its source and the build command are in `ASSETS.lock`; it has not been
  rebuilt byte for byte (a wasm build is not guaranteed to be bit-reproducible). Its behaviour is checked by
  `go test ./x/sovereignty/keeper -run TestVerifyZKProof_RealProof`.
- The experiment results are data from live runs on the testbeds described in the paper; they are not regenerated by a build.
